# Iteration 002 — "3D Arena (test)" mode, v0.2.0 (2D vs 3D side by side)
- Date: 2026-11-27
- Prompts: logged by the main session in `prompts/` (this work was a delegated subagent brief)

## Goal
The user asked to try Hookmaw in 2.5D/3D. Add a selectable **"Play 3D Arena (test)"** mode to the
same build so 2D and 3D can be compared directly, with identical gameplay (same rules on the XZ
plane, same controls) and the 2D mode unchanged. Order: shared logic → 3D view → feel → builds → docs.

## What we did
- **Shared logic.** The rules were already a node-free sim (`scripts/core/arena_sim.gd`). What was
  still inside the 2D scene was the run loop: device → `InputFrame` (mouse/right-stick aim, aim
  assist), hook/dodge press buffers, **hitstop**, bot/auto-evolution, stepping. Moved it to
  `scripts/core/arena_driver.gd` (`ArenaDriver`, RefCounted, signals `stepped` / `auto_chose`,
  pure `make_frame()` and `assist()`), and `scripts/game.gd` now uses it (same behaviour; the 70
  existing tests stayed green before any 3D code existed). Added `ArenaSim.snapshot()` (rounded
  gameplay state) and a `seed_value` on both scenes for tests. `Hud.world_to_screen` (optional
  callable) lets the 3D view place the off-screen boss arrow.
- **3D view** (`scenes/game_3d.tscn`, `scripts/game_3d.gd`, `scripts/view3d/`):
  - `ArenaSpace`: sim (x, y) px → world (x, ·, y) × 0.01; mouse aim = camera ray hit on the plane
    at Morsel's centre height (`screen_to_sim`). Controller aim and aim assist are the shared code.
  - Camera: perspective, 55° down, smooth follow with aim look-ahead, distance 3.8 × k^1.15
    (k = the 2D zoom factor, so it pulls back a bit more than 2D as you grow), trauma shake via
    `h_offset`/`v_offset`, fog density scaled to the camera distance.
  - `Creature3D`: Morsel + 6 kinds built from spheres / cones / capsules / cylinders at unit
    radius, scaled to the sim radius. Eyes with pupils that look at the target, blink, squint
    (happy/hurt/stunned), shrink when hooked, angry brows on telegraphs. Squash/stretch on throw,
    yank, eat, dodge and speed; under-damped size "pop" spring per meal. Trait parts are real
    meshes prebuilt to level 6 and switched on per level: speed fins + tail fin, pierce spines,
    armour plates + band, power horns (grow with level). Shellback's shield lifts to bite,
    puffer spikes swell and whiten, jelly tentacles sway, boss jaw/teeth/lantern turn red on a charge.
    Eaten prey slide into the mouth and shrink. Shadow blob + coloured light pool under every creature.
  - Hook line: camera-facing ribbon (`ImmediateMesh`) along a sagging rope curve; a sag spring
    goes slack on the throw and snaps tight with an overshoot on the catch and each yank; faint
    rope shadow on the seabed; 3D hook heads (bulb, barb, eye ring, halo). The lure's
    `OmniLight3D` rides the hook when it is thrown.
  - Underwater set (`Seabed3D`): shader seabed (radial gradient, sand patches, silt, two-scale
    animated caustics), glowing arena rim, 180 low-poly rocks (inner scatter + wall ring),
    240 swaying kelp (vertex-shader sway), 90 pulsing anemones — all MultiMeshes; 7 additive
    god-ray shafts and marine snow that follow the camera; fog, filmic tonemap, glow; 1
    directional light + 2 omni lights (lure, boss lantern), no shadow maps.
  - FX: bubble bursts + coloured chunks (`CPUParticles3D`) on eat / bite / catch / dodge,
    expanding rings on the play plane, emissive spit shots with halos, aim-preview dots.
  - HUD, sounds, banners, evolution cards, records and pause menu are the same nodes as 2D.
- **Renderer: Compatibility (OpenGL 3.3 / GLES3), unchanged.** It is the project's renderer already
  (2D depends on it), it is the safest on Apple Silicon + Intel Macs, it renders under Xvfb/llvmpipe
  here (all screenshots) and exports fine. Everything used (custom spatial shaders, fog, glow,
  MultiMesh, CPUParticles3D, ImmediateMesh, billboards) works on it. Forward+/Mobile were not tried:
  no visible gain for this low-poly look and a per-project renderer switch would also touch 2D.
  Added `msaa_3d = 2x`. Budget: ~30 low-poly meshes per creature, 3 lights, no shadow maps.
- Title: new **Play 3D Arena (test)** button. Version 0.2.0 (project + presets + title).

## What we learned (→ memories/)
- Godot billboards (`BILLBOARD_ENABLED` / `BILLBOARD_PARTICLES`) ignore node and particle scale
  unless `billboard_keep_scale = true`; our halos and marine snow rendered as huge 2-unit squares
  clipped by the seabed. Glow near the ground reads better as a horizontal additive pool on the
  floor. → `memories/tech/godot-3d-billboards-need-keep-scale-floor-glow-pools`
- Putting the run loop (input mapping, buffers, hitstop, stepping) in a node-free driver shared by
  two views made "the 3D view plays exactly like 2D" a cheap snapshot-equality test; hitstop has
  to live there because it decides when the sim steps. →
  `memories/tech/share-run-loop-driver-across-views-and-test-snapshot-parity`
- Also seen: release exports refuse a scene path on the command line ("compiled without support
  for path overrides"), so a test mode needs a menu entry (or debug-only autoplay) to reach it.
  The camera must look at the play plane (creature centre height), not the floor, or big
  creatures drift to the top of the screen.
